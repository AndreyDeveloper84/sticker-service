# MAX Screen Inventory v0.1

Статус: DRAFT

## Цель

Зафиксировать пользовательские состояния MAX-бота для MVP. Бизнес-логика общая с Telegram; здесь описана MAX-поверхность.

## MAX-specific решения

1. Используем inline keyboard и callback events для основных действий.
2. Бот работает через Webhook в production; long polling не закладываем как production-механизм.
3. Медиа и изображения отправляются средствами Bot API.
4. Mini App не обязателен для первой версии, но архитектура не должна запрещать его подключение позже.
5. Native создание пользовательского sticker set не считаем доступной возможностью, пока она не подтверждена официальным API. Core delivery не должен зависеть от неё.
6. Способ оплаты изолируется в `MaxPaymentAdapter` и не копирует Telegram Stars.

## Не проектировать пока

- обязательный Mini App;
- отдельную бизнес-логику MAX;
- собственный набор статусов заказа;
- функции, существование которых не подтверждено MAX API;
- несколько персонажей в одном заказе.
