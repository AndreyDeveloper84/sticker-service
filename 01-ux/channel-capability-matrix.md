# Channel Capability Matrix v0.1

Статус: DRAFT

Цель документа — не заставлять Telegram и MAX иметь одинаковую техническую реализацию. Паритет требуется на уровне продукта.

| Возможность | Telegram | MAX | Решение |
|---|---|---|---|
| Запуск бота | Да | Да | Реализовать |
| Выбор продукта | Да | Да | Реализовать |
| Кнопки / действия | Да | Да | Реализовать |
| Загрузка фотографий | Да | Да | Реализовать |
| Отправка preview | Да | Да | Реализовать |
| Revision flow | Да | Да | Реализовать |
| История заказов | Да | Да | Реализовать через backend |
| Оплата | Отдельная интеграция | Отдельная интеграция | Разделить payment adapters |
| Выдача изображений | Да | Да | Реализовать |
| Native sticker pack | Поддержка должна использоваться при возможности | Требует отдельной верификации реализации | Не связывать core с этой возможностью |
| Deep links | Поддерживаются каналом | Требует channel-specific реализации | Через adapter |
| Mini App | Возможен | Возможен | Не обязателен для первого MVP |

## Архитектурное правило

Core backend не должен напрямую зависеть от Telegram API или MAX API.

Вместо этого используются контракты:

```text
ChannelAdapter
- send_message()
- send_media()
- request_photo()
- send_preview()
- notify_status()
- deliver_order()
```

Channel-specific capabilities добавляются как отдельные расширения.
